# Markups and PDF round trips

`@nb/markup` reads annotations out of PDFs (`src/import.ts`, `src/bluebeam.ts`), writes them back
(`src/export.ts`), and reads and writes XFDF, FDF and Bluebeam's own files (`.bax`, tool sets, line
styles, hatches: `src/bax.ts`, `src/revuWrite.ts`, `src/toolchest.ts`, ...). What it writes is
the user's saved file, opened later by Bluebeam Revu, Acrobat and other viewers. A mistake here
loses or corrupts people's work, so changes to what is written need the maintainer's agreement.

## Rules

- **Unchanged markups are written back exactly as they were.** An imported markup keeps its
  original annotation in `pdfAnnot` with a `digest` (`src/digest.ts`); if `unchangedSinceImport`
  is true, export keeps the original annotation object untouched. Keys we do not understand must
  survive a save. Fields that do not change the saved annotation are in `IGNORED` in `digest.ts`.
- **Unset is not empty.** Export options such as `assemblies`, `estimating` and `portals` (kept in
  the catalog as `/NBAssemblies`, `/NBEstimating`, `/NBPortals`) leave the file's own data alone
  when `undefined`; an empty list removes it. Keep that distinction.
- **Our private data lives under `/NB...` keys** and is ignored by other viewers. Anything another
  viewer should show goes in the standard annotation (appearance stream, `/Contents`, `/Subj`, ...).
- **Write valid PDF.** Round-trip tests check written bytes with `assertValidPdf` from
  `test/qpdf.ts` (`qpdf --check`). CI sets `REQUIRE_QPDF_TESTS=1`, so a missing qpdf fails there;
  locally the check is skipped if qpdf is not installed.
- **Bluebeam compatibility comes from the format, not from Bluebeam's code.** Do not copy code,
  resources or files from Bluebeam or other proprietary tools, or from projects with licences
  incompatible with Apache-2.0 (see CONTRIBUTING.md). Learn from files you made yourself and from
  the PDF specification.
- **No client files.** Revu-made fixtures for the compatibility matrix are read from
  `reference_data/` (not committed; `test/compat/revu-fixtures.md`). Committed fixtures are made
  by code. `docs/compatibility.md` is generated by `pnpm --filter @nb/markup compat`; do not edit it
  by hand.

## Testing a change

A change to import or export needs a round-trip test: build or import a markup, export it, load
the bytes again (pdf-lib), and assert on the dictionary and on the re-imported markup. Assert
both an edited markup and an unchanged one (unchanged must compare equal to the original), as
`src/bluebeam.test.ts` does. Test files are `src/*.test.ts`: this package's glob is not recursive,
so keep tests directly in `src/` or add them to the `test` script.
